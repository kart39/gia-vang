# Giá vàng theo giờ — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ghi giá vàng (SJC, nhẫn trơn, XAU) mỗi giờ bằng GitHub Actions và hiển thị trên một trang GitHub Pages để canh thời điểm mua.

**Architecture:** Script Python (stdlib) lấy giá từ PNJ + gold-api, append vào `data/history.json`, workflow commit mỗi giờ. Trang tĩnh `index.html` đọc file đó; logic thuần nằm trong `assets/logic.js` (test bằng `node --test`), phần DOM/Chart.js trong `assets/app.js`.

**Tech Stack:** Python 3.12+ stdlib + unittest; GitHub Actions; HTML/CSS/JS thuần (ES modules); Chart.js 4 từ cdnjs; Node 20+ test runner.

**Spec:** `docs/superpowers/specs/2026-11-23-gia-vang-design.md`

## Global Constraints

- Nguồn PNJ: `https://edge-api.pnj.io/ecom-frontend/v1/get-gold-price?zone=00`, lấy `masp` `"SJC"` và `"N24K"`, trường `giamua`/`giaban`, đơn vị **nghìn đồng/chỉ**.
- Nguồn thế giới: `https://api.gold-api.com/price/XAU`, trường `price`, USD/ounce.
- Bản ghi: `{"t": ISO-8601 UTC "YYYY-MM-DDTHH:MM:SSZ", "sjc_buy", "sjc_sell", "ring_buy", "ring_sell", "xau_usd"}`; trường lỗi = `null`; cả hai nguồn lỗi → không ghi, không commit.
- Cron `5 * * * *`. Repo public, tên `gia-vang`, Pages từ nhánh `main` thư mục gốc.
- Hiển thị: triệu đồng/lượng (= nghìn/chỉ ÷ 100), dòng phụ triệu/chỉ; XAU USD/oz. Giờ hiển thị theo Asia/Ho_Chi_Minh.
- Biểu đồ: đoạn tăng xanh, giảm đỏ, ngang xám; giờ thiếu để trống (không nối).
- Cảnh báo "dữ liệu cũ" khi bản ghi mới nhất > 3 giờ.
- Giá muốn mua so với **giá bán**, lưu `localStorage` key `giavang.targets`, mọi truy cập bọc try/catch.
- Trang tự tải lại dữ liệu mỗi 10 phút. Giao diện ưu tiên điện thoại, không cuộn ngang.

## Review Focus

1. PNJ đổi cấu trúc / thiếu mã SJC hoặc N24K → trường đó `null`, script không crash (test ở Task 1).
2. Một nguồn timeout/lỗi mạng → vẫn ghi nguồn còn lại (Task 1).
3. `history.json` rỗng (`[]`) ngay sau khi deploy → trang hiện "Chưa có dữ liệu", không lỗi JS (Task 2 `latest([])`).
4. Người dùng nhập giá kiểu Việt "132,5" hoặc "132.5" → hiểu đúng 132.5; chuỗi rỗng → bỏ mục tiêu (Task 2 `parseTarget`).
5. Chạy tay trùng giờ (workflow_dispatch) → biểu đồ lấy bản ghi cuối của giờ đó, không nhân đôi điểm (Task 2 `hourlySeries`).

### Task 2: Logic hiển thị (thuần, có test)

**Files:**
- Create: `assets/logic.js` (ES module), `tests/logic.test.mjs`, `package.json` (`{"type":"module","private":true,"scripts":{"test":"node --test tests/"}}`)

**Interfaces:**
- Consumes: định dạng bản ghi của Task 1.
- Produces (export từ `assets/logic.js`):
  - `toLuong(perChiThousand: number|null) -> number|null` (÷100)
  - `toChi(perChiThousand) -> number|null` (÷1000, triệu/chỉ)
  - `latest(history: Rec[]) -> Rec|null`
  - `change24h(history, field: string) -> {diff:number, dir:'up'|'down'|'flat'}|null` — so bản ghi mới nhất với bản ghi gần nhất tới mốc `t-24h` trong khoảng ±90 phút; diff theo đơn vị gốc của field
  - `isStale(latestIso: string, nowMs: number, hours = 3) -> boolean`
  - `hourlySeries(history, field, sinceMs, untilMs) -> {x:number, y:number|null}[]` — một điểm cho mỗi giờ (làm tròn xuống) từ `sinceMs` đến `untilMs`; giờ thiếu `y:null`; nhiều bản ghi cùng giờ → lấy bản cuối
  - `segmentDir(y0, y1) -> 'up'|'down'|'flat'`
  - `parseTarget(input: string) -> number|null`
  - `targetHit(sellPerChiThousand: number|null, targetLuong: number|null) -> boolean` — `toLuong(sell) <= target`; null ở đâu → false
